# Mag 现货提示系统 - 更新日志

## v2.6.0 (2026-08-14)

### 新增功能 ✨

#### 标的可视化页面
直观查看单个标的的进/退场期、场外指数、爆破指数变化，并叠加真实日 K 线。

**页面（三面板联动）:**
- 顶部：真实日 K 线（蜡烛图，涨绿跌红）
- 中部：场外指数（含 1000 均衡线、1500 参考线）
- 底部：爆破指数（含 200、0 关键阈值线）
- 进/退场期背景色块贯穿三面板，逼近日三角标记，标的下拉选择+筛选，X 轴联动缩放
- **分享按钮**：一键把当前图表导出为带标题（标的名/分类/日期范围/Mag 水印）的分享卡片 PNG，文件名 `Mag_<标的>_<最新日期>.png`

**两种使用方式:**
- **API 实时页面**：`GET /chart` —— 数据实时读库，`mag_system` 导入后刷新即更新；配套 `GET /chart/data` 数据接口
- **静态生成**：`./mag_chart.sh` 生成自包含 `mag_chart.html`，离线可看

**真实 K 线接入:**
- 加密走 Binance 现货、美股/商品/亚股走 Yahoo Finance；国内 A 股篮子无公开行情源，仅显示场外/爆破两栏
- **惰性刷新缓存**：页面加载时，若当天 K 线尚未更新则后台增量抓取并存库，一天最多一次，后续访问者直接读缓存、不重复拉取
- 新增 `src/kline_sources.py`（标的→行情源映射）、`src/fetch_kline.py`（抓取/缓存）、`src/gen_chart.py`（页面生成）

#### 解析巡检工具
- 新增 `src/audit_parse.py` / `mag_audit.sh`：比对笔记「数据行」与「实际解析出的标的」，一次性揪出所有漏解析的行（缺"数"、括号异常、爆破同行、数值笔误等），输出疑似漏解析明细供人工核对，快速区分是解析器缺口还是源数据笔误

### 变更 🔧

#### 国内A股/商品分类调整
- **国内生猪、地产** 归为**国内A股**（`is_cn_stock`），不再作为美股/大宗商品（`is_us_stock`）
- 国内A股板块内各标的（A股指数、国内人工智能、国内机器人、国内生猪、地产等）**彼此平级、互不对标**，各自独立分析

#### 质量劣化判定周期统一
- **国内A股（`is_cn_stock`）质量劣化判定改用 14 次周期**（与美股一致），原为 7 次；普通币种仍为 7 次

#### 退场期质量劣化补对称条件
- 退场期新增"爆破均值上升"条件，与进场期对称：
  - **进场期**：满周期时，爆破未破 200 **且** 均值下降 → 质量劣化
  - **退场期**：满周期时，爆破未跌破 0 **且** 均值上升 → 质量劣化

### Bug 修复 🐛

- **国内生猪解析失败**：源笔记"国内生猪 （预测消费cpi)"用了全角"（" + 半角")"混合括号，原正则要求全角"）"，导致整条解析失败、生猪从未入库。括号正则兼容半角右括号，并允许币名与括号间存在空格
- **质量劣化趋势判断方向错误**：`section_data` 源自 `get_coin_history()`（按日期倒序），导致前后半段颠倒、趋势判断与真实时间相反——进场期爆破在时间上"上升"（好事）时反而误判劣化、"下降"时漏判。改为按日期正序排序
- **期权波动率大量漏解析**：其格式为"期权波动率（比特币Vega交易）"名字单独一行（括号紧跟无空格、括号内含 Vega 字母）+ 场外指数/进退场同行 + 爆破单独行，两个解析缺口叠加导致 470 次出现仅入库 4 条。修复：中文币名括号前允许无空格（`\s*（`）；format3 新增"场外指数+进退场同行、爆破在其它行"格式。重新导入后 4→463 条
- **假标的污染下拉菜单**：笔记里的说明句（"外部性在所有币种中表现最好"）与已弃用聚合名（"美股 OTC"、"国内股OTC"）曾被误当成标的录入。新增解析忽略名单跳过，并清理历史记录
- **爆破指数与名字/场外挤同一行漏解析**：`_extract_coin_data` 原只从名字行的下一行找爆破指数，当"名字 场外指数X 进退场期Y天 爆破指数Z"全写在一行时扫不到、整条丢弃。改为先看名字行本身是否含爆破。所有此类写法的标的受益
- **format2"名字+场外+爆破"同行多写法漏解析**：名字与"场外指数"之间夹了字母标识（如白银的 Xag）或括号说明（如地产）时 format2 匹配失败、整条丢弃，导致白银等大量缺失。修复：format2 名字部分对齐 format1（允许字母标识、括号、负爆破、爆破前空格），并支持"名字+场外+爆破+进退场全挤一行"（如 PLtr）。经解析巡检确认，漏解析行从约 470 降到 20（仅剩单个已停更币种的源数据简写）
- **黄金分类不一致**：GOLD 不在美股白名单，其"美股/大宗"标记仅依赖当天"大宗$美股区"区域是否被识别到，个别笔记漏识别区域时被误标为山寨币（125/472 条），导致图表将黄金显示为山寨币。改为对 GOLD/白银/铜/OIL 无条件归为美股/大宗（`is_us_stock=1`），并修正历史误分类记录

### 改进 ⚡

- **质量劣化趋势判断改用最小二乘线性回归斜率**：替代原"前后半段均值比较"（把整段压成两个聚合数、丢失形态、对尖峰/噪声敏感）。新算法用全部数据点拟合，`slope < 0` 判下降、`slope > 0` 判上升，对异常值更稳健，并为未来加显著性阈值预留接口

### 文档 📖

- **对标链图修正**：国内A股板块内标的原用 `↓` 画成层级（A股指数→国内人工智能→国内机器人），实际彼此平级、互不对标，改为并列结构并同步说明

## v2.5.0 (2026-08-14)

### 新增功能 ✨

#### 导入去重（低频/重复数据自动跳过）
低频更新标的（国内A股、地产等）常在源笔记中被逐日重复记录，造成大量冗余。现在**所有标的**在导入时若与"前一交易日"完全相同则跳过写入。

**判定条件（四者全等才算重复）:**
- 场外指数、爆破指数、进/退场类型、进/退场天数

进/退场天数每日递增，正常推进的标的天数不会全等——只有源把同一快照重复记录时才会触发。天数不同则即使场外/爆破相同也照常写入。

**实现:**
- **database.py**: `insert_or_update_coin_data()` 写库前比对前一交易日，返回 `True`（已写入）/`False`（跳过）；新增辅助方法 `_is_same_record_for_dedup()`
- 置于唯一写库出口，对 HTML 批量、Notion 逐日、手动/CSV/JSON 等所有导入路径一致生效

#### 导入前校验（拒绝重复日期与未来日期）
通过 Notion 链接（API/JSON 模式）导入时，解析出日期后、写库前增加两道校验：
- **情况一**：数据库已存在该日期数据 → 拒绝，返回"已存在，请勿重复导入"
- **情况二**：日期为未来时间 → 拒绝，返回具体日期与今天

两者返回 `success=False`，经 API 端点转为 HTTP 400 并带中文拒绝原因；新增 `database.py` 的 `date_exists()` 方法。

### Bug 修复 🐛

#### Notion/HTML 解析健壮性
- **"场外指数"缺"数"字**：笔记中 NVDA 长期误写为"场外指977"（漏"数"），导致所有正则匹配失败、整条被丢弃——NVDA 自 2025-12-17 起 194 处、约 8 个月未能入库。将各正则的"数"设为可选（`场外指数?`），缺字也能识别
- **场外指数与数字间空格**："铜 场外指数 1025"这类带空格写法整条解析失败被丢弃，改为 `场外指数?\s*(\d+)` 兼容
- **逼近漏检**：单独成行的"逼近"被中文币名停止条件误判为币名而提前 break，导致漏检；从停止条件中排除"逼近"
- **黄金爆破指数漏抓/串值**：`re.match` 行首锚定无法识别"场外退场期第45天  爆破指数7"这类爆破指数位于行中部的写法，导致黄金整条丢失或误抓下一标的的值，改为 `re.search`
- **HTML 导入日期格式**：日期行识别正则仅匹配"M.D"（如 5.19），无法识别带年份的"YYYY.M.D"（如 2026.6.13），导致绝大多数笔记被跳过；放宽为可选年份前缀

#### 数据库表结构
- **基础建表补充 `is_cn_stock` 列**：该列此前仅通过迁移脚本 ALTER 添加到旧库，`init_database()` 的 CREATE TABLE 缺此列，导致删库后重建的新库缺列、导入报 "no such column: is_cn_stock"。补入基础建表，使"删库 + 重新导入"可直接工作

#### 展示
- **国内A股对标链显示**：国内A股标的与美股平级、本就不构建对标链，但展示层兜底仅识别美股与 BTC，导致 A股指数/国内人工智能/国内机器人显示"数据不足"。将 `is_cn_stock` 并入顶层标的，正确显示"顶层参考指标"

## v2.3.0 (2025-10-16)

### 重大修复 🐛

#### 修复退场期涨幅计算逻辑错误
修正了基础涨幅和相变修正在进退场期的计算逻辑，之前的实现只适用于进场期。

**问题描述:**
旧版本的计算逻辑：
```python
base_change = ((current_index - ref_index) / ref_index) * 100
phase_correction = 5 if current_index > ref_index else -5
```
这个逻辑只对进场期正确，对退场期完全错误。

**正确规则:**

1. **基础涨幅:**
   - 进场期：场外指数变高→涨幅为正，场外指数变低→涨幅为负
   - 退场期：场外指数变高→涨幅为负，场外指数变低→涨幅为正（完全相反）

2. **相变修正:**
   - 进场期：从<1000→>=1000 +5%，从>=1000→<1000 -5%
   - 退场期：从<1000→>=1000 -5%，从>=1000→<1000 +5%（完全相反）

**实现细节:**
- analyzer.py: 重构 `_calculate_change_percentage()` 方法
- 新增 `phase_type` 参数，根据进退场期调整计算逻辑
- 退场期的基础涨幅和相变修正都反向

**测试验证:**
- test_phase_logic.py: 完整的单元测试
- 验证进场期基础涨幅计算
- 验证退场期基础涨幅计算（反向）
- 验证进场期相变修正
- 验证退场期相变修正（反向）

**影响范围:**
此bug影响所有退场期的分析结果，修复后需要重新分析历史退场期数据。

新增对"逼近"状态的自动检测和修正规则：

## v2.0.0 (2025-10-16)

### 重大改进 🚀

#### 支持乱序和缺失日期录入
之前的版本严格依赖数据按日期顺序录入，现在完全支持：
- ✅ 任意顺序录入数据（可以先录10-15，再录10-11）
- ✅ 跳过某些日期后续补录
- ✅ 补录后重新分析得到正确结果

### 核心技术改进

#### 1. 数据库层 (database.py)
新增方法：
- `get_previous_day_data(coin, date)` - 查找真正的前一天数据
- `get_next_day_data(coin, date)` - 查找真正的后一天数据
- `find_crossing_node(coin, before_date, threshold, direction)` - 通用的跨越节点查找
- `delete_analysis_results(start_date, end_date)` - 删除旧分析结果
- `get_data_in_range(start_date, end_date)` - 获取日期范围数据

#### 2. 分析器层 (analyzer.py)
重构关键方法：
- `_detect_key_node()` - 使用 `get_previous_day_data()` 代替数组索引 `history[1]`
- `_find_reference_node()` - 使用 `find_crossing_node()` 查找参考节点
- 所有插值计算改用明确的日期查询而非数组遍历

#### 3. 新增工具 (mag_reanalyze.py)
全新的重新分析工具：
```bash
# 重新分析单个日期
python3 mag_reanalyze.py 2025-10-14

# 重新分析日期范围
python3 mag_reanalyze.py 2025-10-10 2025-10-15

# 重新分析指定币种
python3 mag_reanalyze.py 2025-10-10 2025-10-15 BTC ETH
```

### 问题修复

#### 修复前的问题
```python
# 旧版本的错误假设
history = db.get_coin_history(coin, limit=5)
today = history[0]       # ❌ 可能不是今天
yesterday = history[1]   # ❌ 可能不是昨天，可能是3天前！
```

**影响**：
- 如果日期乱序录入，会把错误的日期当作"昨天"
- 如果缺失日期，会跨越多天导致关键节点检测失败
- 插值计算使用不相邻的数据，误差可能达到85+点

#### 修复后的实现
```python
# 新版本使用日期查询
previous_data = db.get_previous_day_data(coin, current_date)  # ✅ 真正的前一天
```

**改进**：
- 无论数据如何录入，都能找到正确的前一天
- 即使缺失日期，也能准确计算
- 补录数据后重新分析即可更新结果
